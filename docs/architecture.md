# Карта проекта

## Владение состоянием

| Модуль | Ответственность |
| --- | --- |
| `src/main.ts` | Создание систем, фиксированный шаг симуляции, цикл кадра и связь систем |
| `src/world.ts`, `src/profiles.ts` | Данные карты, проверка импорта, миграции и архитектурные профили |
| `src/worldRenderer.ts` | Текущая карта, экземпляры зданий, общая геометрия, ячейки, LOD и освобождение мешей |
| `src/editor.ts`, `src/ui.ts` | Редактирование карты, манипуляторы, сохранение/импорт/экспорт и интерфейс |
| `src/gameInput.ts` | Клавиши, мышь, распознавание двойных нажатий и одноразовые команды |
| `src/player.ts`, `src/character.ts` | Физика движения; модель персонажа, поза и выбор анимации |
| `src/sceneCameras.ts`, `src/followCamera.ts` | Камеры, сохранение редакторского ракурса, препятствия и прозрачность |
| `src/architecture.ts`, `src/streets.ts` | Геометрия архитектурных профилей и процедурной среды |
| `src/cityMaterials.ts`, `src/surfaceDetail.ts` | Материалы, текстуры и подавление повторяющихся деталей вдали |
| `src/dayNight.ts`, `src/beacons.ts` | Время суток, освещение и маячки |
| `src/renderSettings.ts`, `src/lodTransitions.ts`, `src/nearbyMeshes.ts` | Бюджеты рендера, плавные LOD и локальные выборки коллизий |

Редактор изменяет `city.world`, а `WorldRenderer` владеет связанными ресурсами Babylon.
При полном `rebuild` удаляются старые экземпляры, прототипы и процедурные меши, затем
создаются новые. При удалении отдельного объекта используется `removeMesh`: редактору
не нужно знать устройство его LOD. Коллайдеры существуют независимо от видимого LOD.
После изменения карты основной модуль обновляет источники локальных выборок и освещения.

Ввод накапливает команды между шагами симуляции: даже два нажатия между кадрами не теряются.
`player.ts` получает `PlayerInput`, не обращаясь к DOM. `Character` применяет результат к модели.
Физика обновляется с шагом 1/60 с, а камера, анимация, свет и переходы LOD — каждый кадр.
Пересмотр LOD ограничен интервалом из `renderSettings.ts`; начальная сцена сразу получает
нужные уровни. В игре LOD ориентируется на героя, в редакторе — на камеру.

## Где оптимизировать

Сначала измеряйте время кадра и число активных мешей на целевом GPU. Общие ограничения
разрешения, частоты LOD, ячеек, дистанций уличных деталей и локального поиска коллизий
находятся в `renderSettings.ts`. Конкретные архитектурные дистанции принадлежат шаблонам карты.
Объединение геометрии и инстансы меняются в `architecture.ts`, `streets.ts`, `worldRenderer.ts`;
стоимость материалов — в `cityMaterials.ts`, света — в `dayNight.ts`.
Отключение ячейки скрывает готовые меши, а не выгружает их из памяти.

## Генератор города

`scripts/build-chicago.py` остаётся точкой запуска: читает исходники и собирает результат.
Алгоритмы разделены по предметным областям без изменения формата данных:

- `chicago_geometry.py` — проекция, контуры, триангуляция и дно;
- `chicago_roads.py` — дорожная сеть, поверхности, фонари, светофоры и переходы;
- `chicago_railway.py` — эстакада, фермы и размещение опор;
- `chicago_buildings.py` — размеры, размещение зданий и групп достопримечательностей.

Готовые геоданные хранятся в проекте. Запуск игры не требует Python или сети.
Для пересборки: `python3 -m pip install -r scripts/requirements.txt`, затем `npm run city:build`.
Источники и ограничения точности описаны в [данных Чикаго](../data/chicago/README.md).

## Проверки и совместимость

- `npm test` — тесты TypeScript, включая ввод и жизненный цикл городских ресурсов (Node.js 24+).
- `npm run test:geometry` — геометрические тесты Python после установки requirements.
- `npm run build` — проверка типов и production-сборка.

Импорт и сохранённая карта проходят `parseWorld` до применения. Версия карты остаётся 3;
ключ карты `block-district-chicago-v3`, ракурса `block-district-editor-camera-v1`, времени суток
`block-district-time-of-day-v1`. Рефакторинг не меняет эти ключи и не требует сброса сохранений.
Браузерная проверка дополнительно должна покрывать старт, управление, редактор, пересоздание
сцены, импорт/экспорт и восстановление после перезагрузки: unit-тесты не заменяют WebGL.
